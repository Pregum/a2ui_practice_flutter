## 事前準備（会場に行く前）

1. Pixel 6a の充電・画面ロック解除時間を最大に。
2. モデルがあるか確認（無ければ `scripts/push_gemma_model.sh` で push）:
   ```
   adb shell ls /storage/emulated/0/Android/data/com.xtone.a2ui_support_demo/files/
   # → gemma-4-E2B-it.litertlm (2.6GB) があればOK
   ```
3. 最新 APK を入れる（**`adb install -r` なら モデルは消えない**。アンインストールすると消えるので注意）:
   ```
   flutter build apk --release --target-platform android-arm64
   adb install -r build/app/outputs/flutter-apk/app-release.apk
   ```
   ※ `flutter` は mise 経由（プロジェクトの `mise.toml` で 3.44.1 に固定済み。`flutter pub get` が SDK エラーになったらこのファイルがあるか確認）。
4. アプリを一度起動 → **Gemma に切替**（ローカルモデルなので約10秒でロード、DLなし）→ 「請求の問い合わせ」を1回流して動作確認。
5. 機内モードON（オフライン訴求。モデルはロード済みなので影響なし）。

## 本番の流れ（スライド25「実機デモ」〜26「本命デモ」）

1. **請求の問い合わせ**（reactive の代表）
   - プリセットチップをタップ → 約2秒で最初のトークン、**25〜35秒**で画面完成。
   - 話すこと: progressive rendering（ログに JSONL が流れ、画面が組み上がる）/ 検証OK のログ。
2. **働きすぎ検知**（proactive の見せ場）
   - 2回目以降は「エンジン再初期化中」が **+5〜10秒** 入る（縮退ループ対策。仕様として一言添えてもよい）。
   - 話すこと: 頼んでいないのに UI が向こうから現れる未来。

## 失敗したときのフォールバック（多段構え）

1. **同じプリセットをもう一度タップ** — 生成のたびにエンジンを作り直すので、再試行は毎回フレッシュな状態。
2. **アプリを再起動して再試行** — タスクキルしても モデル再ロードは約10秒。
3. **Mock に切替えて実演** — 同じ A2UI パイプラインを台本で流す（速度プリセットで演出可）。
4. **スライドの実キャプチャ** — スライド25/26の画像は本日 Pixel 6a 実機 Gemma で生成・検証OKの実物。

## 既知の技術メモ（質問が来たら）

- flutter_gemma 0.16.4 には「連続生成で2回目以降が縮退ループになる」KVキャッシュ汚染バグがあり、0.16.5 でも完治せず。**生成ごとにエンジンを再作成**することで回避（`FlutterGemmaLlm._recreateEngine`）。モデルファイルは OS のページキャッシュに乗るため再作成は5〜10秒。
- 実測（Pixel 6a・GPU・オフライン）: 初回トークン約2秒 / 1画面25〜35秒。
- 小型モデル対策: シナリオ別 few-shot 1例だけの簡約プロンプト（`compactSystemPromptFor`）+ 暴走ガード（有効メッセージなしで2000字打ち切り）+ 閉じ括弧の自動修復。
